## 実装方式解説書: Alt-IME スイッチャー

### 1. 目的
本ドキュメントは、「Alt-IME スイッチャー」のコア機能を実現するための具体的なプログラミング手法と、その背後にあるロジックを解説する。

### 2. 基盤技術: 低レベルキーボードフック
本アプリケーションの心臓部となるのは、Windows APIの**`SetWindowsHookEx`** を用いてシステムに登録する**低レベルキーボードフック (`WH_KEYBOARD_LL`)** である。

これにより、キーボードドライバから送られるキー入力イベントを、個別のアプリケーションにディスパッチされる前の段階で捕捉することが可能となる。実装の際は、キーが押されたことを示す **`WM_KEYDOWN`** / **`WM_SYSKEYDOWN`** と、キーが離されたことを示す **`WM_KEYUP`** / **`WM_SYSKEYUP`** の両イベントを監視下に置く。

### 3. 中核ロジック: 「単押し」と「組み合わせ押し」の判定
正しい動作のためには、`Alt`キーの「単押し」と他のキーとの「組み合わせ押し」を厳密に区別する必要がある。これは、以下の状態管理と判定フローによって実現する。

#### 3.1. 状態管理
プログラムは、現在のキーボードの状態を追跡するために、少なくとも以下の3つの内部フラグ（変数）を保持する。

* `isLeftAltDown`: 左Altキーが現在押されているかを示すフラグ (`true`/`false`)
* `isRightAltDown`: 右Altキーが現在押されているかを示すフラグ (`true`/`false`)
* `isCombinationPress`: Altキーが押されている間に他のキーが押され、「組み合わせ押し」が確定したかを示すフラグ (`true`/`false`)

#### 3.2. 判定フロー
キーイベントが発生するたびに、フックプロシージャ（フック時に呼び出されるコールバック関数）内で以下の判定が実行される。

**ステップ 1: `Alt`キー押下時 (KeyDown)**
1.  押されたキーが左Altまたは右Altであることを確認する。
2.  対応するフラグ（例: `isLeftAltDown`）を `true` にセットする。
3.  **このキーイベントをここでブロックする。** OSやアプリケーションには通知せず、フックプロシージャから `1` を返してイベントの伝達を止める。
    * **理由:** この段階でイベントを伝達させると、アプリケーションのメニューがアクティブになるなどの意図しない副作用が発生するため。

**ステップ 2: 次のキーイベント発生時**
* **A) 他のキーが押された場合 (`KeyDown`)**
    1.  `isLeftAltDown` または `isRightAltDown` が `true` であることを確認する。
    2.  `isCombinationPress` フラグを `true` にセットする。これにより「組み合わせ押し」が確定する。
    3.  **ブロックしていた `Alt`キーの押下イベントを、`SendInput` APIを用いて能動的にOSへ送信する（イベントの再送）。**
    4.  現在のキー（例: `Tab`キー）の押下イベントを、**`CallNextHookEx`** APIを呼び出してOSへ渡す。
    5.  以降、`Alt`キーが離されるまで、全てのキーイベントは `isCombinationPress` フラグを基に `CallNextHookEx` でOSへ素通しする。

* **B) `Alt`キーが離された場合 (`KeyUp`)**
    1.  `isCombinationPress` フラグを確認する。
    2.  フラグが **`false`** の場合、**「単押し」が確定**する。
    3.  ここで初めて **IME制御処理** を実行する（左Altならオフ、右Altならオン）。
    4.  イベントはブロックしたままなので、副作用は発生しない。

**ステップ 3: `Alt`キー解放時 (`KeyUp`) の最終処理**
* 「組み合わせ押し」であったか「単押し」であったかにかかわらず、`Alt`キーの`KeyUp`イベントを捕捉したタイミングで、全ての関連フラグ（`isLeftAltDown`, `isCombinationPress` など）を `false` にリセットし、次のキー入力に備える。

### 4. IME制御の実装
「単押し」確定時に呼び出すIME制御処理は、以下のWindows APIを順に呼び出して行う。

1.  **`GetForegroundWindow()`**: 現在アクティブなウィンドウのハンドルを取得する。
2.  **`ImmGetDefaultIMEWnd()`**: 上記で取得したウィンドウハンドルを基に、対応するIMEのウィンドウハンドルを取得する。
3.  **`SendMessage()`**: 取得したIMEウィンドウハンドルに対し、`WM_IME_CONTROL` メッセージを送信する。その際、パラメータ `wParam` に `IMC_SETOPENSTATUS` を、`lParam` に `1` (オン) または `0` (オフ) を指定する。

### 5. アプリケーション構造
* 本アプリケーションはGUIを持たないバックグラウンドプロセスとして実装する。
* `SetWindowsHookEx` でセットしたフックを有効に保つため、プログラム内にはメッセージループ（`GetMessage`, `TranslateMessage`, `DispatchMessage`）を必ず含める必要がある。
